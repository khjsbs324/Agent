# 홈페이지 레퍼런스 분석 스킬 인수인계

## 1. 프로젝트 목표

사용자가 수집한 홈페이지 레퍼런스를 읽어 URL과 출처를 정리하고, 디자인·화면 구성·사용자 흐름·문구·콘텐츠·기능을 비교하여 새 홈페이지 제작에 활용할 인사이트를 만드는 Codex 스킬을 개발 중이다.

스킬 이름은 `homepage-reference-analyzer`이며 프로젝트 전용 자동 검색 위치에 있다.

```text
.agents/skills/homepage-reference-analyzer/
```

사용자는 어려운 전문 용어보다 단계별로 짧고 명확하게 설명받는 방식을 선호한다. 한 번에 여러 결정을 요구하지 말고 한 단계씩 진행한다. 사용자가 `중지`, `스탑`, `그만`, `멈춰`라고 하면 즉시 작업을 중단한다.

## 2. 현재 파일 구조

```text
Antigravity/
├─ AGENTS.md
├─ 인수인계.md
├─ 홈페이지_레퍼런스_분석_스킬_예상내용.txt
├─ 리서치/
│  ├─ [리서치 결과]_SEUMIM_신규_웹사이트_기획_레퍼런스_34선.txt
│  ├─ [리서치 결과]_SEUMIM_웹사이트_기획_레퍼런스_200선.txt
│  └─ 명령어 규칙.txt
└─ .agents/skills/homepage-reference-analyzer/
   ├─ SKILL.md
   ├─ agents/openai.yaml
   ├─ references/
   │  ├─ input-rules.md
   │  ├─ analysis-method.md
   │  ├─ output-rules.md
   │  └─ pending-decisions.md
   └─ scripts/
      ├─ collect_references.py
      └─ validate_results.py
```

`AGENTS.md`는 한글 기여 가이드다. 이후 파일 변경 전 반드시 읽고 따른다.

## 3. 확정된 규칙

### 기본 자료

- 파일명에 `[리서치 결과]`가 문자 그대로 들어간 TXT 파일을 항상 기본 자료로 사용한다.
- 조건에 맞는 파일이 여러 개면 모두 사용한다.
- 원본 파일을 수정하거나 덮어쓰지 않는다.
- 같은 홈페이지는 하나로 묶되 모든 원문, 분류, 출처를 보존한다.

### 추가 자료

- 사용자가 `리서치 자료 추가 입력`이라고 명령하면 이어서 제공하는 파일, URL, 텍스트를 추가 자료로 인식한다.
- 추가 자료는 현재 분석에서 사용하지만 사용자 요청 없이 기본 파일에 합치거나 디스크에 저장하지 않는다.

### 결과물

모든 결과는 메모장에서 열 수 있는 UTF-8 TXT로 작성한다.

1. 홈페이지별 분석
   - 홈페이지 이름, URL, 업종
   - 디자인, 화면 구성, 사용자 흐름
   - 문구와 콘텐츠, 주요 기능
   - 장점과 단점, 참고할 부분
2. 전체 비교 분석
   - 공통점, 차이점, 반복 패턴, 눈에 띄는 사례
3. 최종 인사이트
   - 적용 아이디어, 우선 참고 홈페이지, 주의점, 추가 조사 항목

TXT 하나에는 최대 100개만 기록한다. 홈페이지 하나를 결과 1개로 계산하며 하나의 홈페이지 내용을 두 파일로 나누지 않는다.

### 비교 분석 방법

- 고유 홈페이지 수를 분모로 사용한다.
- 공통 패턴: 30% 이상
- 반복 패턴: 10% 이상 30% 미만
- 특이 사례: 10% 미만이지만 참고 가치가 있는 사례
- 사실과 해석을 분리하고 모든 핵심 결론에 출처를 연결한다.

## 4. 데이터 사전 조사 결과

기존 PowerShell 조사 기준이며 스킬 스크립트로 검증한 결과는 아니다.

- 원본 URL 기록: 234개
- 고유 URL·도메인: 209개
- 34선 파일: 고유 홈페이지 34개
- 200선 파일: 기록 200개, 고유 홈페이지 175개
- 200선 내부 중복 기록: 25개

따라서 중복 제거 후 홈페이지별 결과는 현재 예상으로 `001-100`, `101-200`, `201-209` 세 파일이다.

## 5. 완료된 작업

- 잘못 생성됐던 사용자 전역 스킬 폴더를 삭제했다.
- 프로젝트 루트에 만들었던 스킬을 `.agents/skills/`로 이동했다.
- 두 기본 리서치 파일 이름에 `[리서치 결과]`를 추가했다.
- 초기 TODO 템플릿을 실제 `SKILL.md` 지침으로 교체했다.
- 입력·분석·출력·미확정 규칙을 참조 파일로 분리했다.
- URL 수집·중복 정리 및 결과 검사 스크립트를 작성했다.
- `agents/openai.yaml`의 CP949 한글 깨짐을 수정하고 UTF-8로 저장했다.
- `AGENTS.md`를 생성한 뒤 한글로 번역했다.

## 6. 반드시 보류할 항목

사용자가 명시적으로 4·5단계 반영과 시험 실행을 제외하라고 했다.

- 4단계: 홈페이지 세부 분류 기준
- 5단계: 홈페이지별 TXT 작성 양식과 레코드 구분 방식

현재 `SKILL.md`는 이 두 항목이 없으면 자료 목록과 중복 현황까지만 처리하고 사용자 입력을 요청하도록 되어 있다. 다음 모델은 임의로 두 기준을 만들거나 전체 분석이 완성됐다고 보고하면 안 된다.

추가 미확정 사항:

- 결과 저장 폴더
- 추가 자료의 지속 저장 여부
- 라이브 URL 직접 조사 여부
- 점수 평가와 항목별 중요도
- 캡처 이미지 분석 여부
- TXT 이외의 기본 자료 확장자

## 7. 시험 및 기술 상태

- `collect_references.py`와 `validate_results.py`는 작성만 했고 실행하지 않았다.
- Python 문법 검사도 사용자의 시험 제외 요청 때문에 실행하지 않았다.
- `quick_validate.py` 실행은 이전에 `PyYAML` 미설치로 실패했다.
- 실제 리서치 분석 결과 파일은 아직 생성하지 않았다.
- 라이브 홈페이지는 조사하지 않았다. 원본 자료에는 이름, URL, 짧은 분류 근거만 있으므로 세부 UX와 최신 기능을 단정하면 안 된다.
- `.git` 폴더는 비어 있으며 현재 디렉터리는 정상 Git 저장소가 아니다. Git 기록과 기존 커밋 규칙은 없다.

## 8. 다음 권장 작업 순서

1. 사용자에게 4단계 분류 기준을 한 번에 하나씩 받는다.
2. 사용자에게 5단계 TXT 작성 예시 또는 원하는 양식을 받는다.
3. 결과 저장 폴더와 라이브 URL 조사 여부를 확인한다.
4. 확정 내용을 `references/`와 `SKILL.md`에 반영하고 미확정 차단 문구를 조정한다.
5. 사용자 허락을 받은 후에만 Python 문법 검사와 스크립트 시험을 실행한다.
6. 소량 자료로 시험한 뒤 209개 전체 자료를 처리한다.

시험 전에는 원본 리서치 파일을 변경하지 말고 모든 시험 출력을 별도 임시 폴더에 저장한다.
