홈페이지 레퍼런스 분석 스킬 예상 내용
====================================

※ 이 문서는 실제 SKILL.md를 만들기 전의 설계 초안이다.
※ 확정된 내용과 아직 결정하지 않은 내용을 구분해서 기록한다.


1. 스킬 기본 정보
-----------------

임시 스킬 이름:
homepage-reference-analyzer

스킬 목적:
여러 홈페이지 레퍼런스를 조사하여 디자인 스타일, 화면 구성, 사용자 흐름,
문구, 콘텐츠, 기능을 분류하고 비교한다.
반복되는 패턴과 차별점을 발견하고 새로운 홈페이지 제작에 활용할
인사이트를 만든다.


2. 스킬이 실행되는 요청 예시
----------------------------

- 홈페이지 레퍼런스를 분석해줘.
- 리서치 결과를 분류해줘.
- 참고할 만한 홈페이지의 공통점을 찾아줘.
- 레퍼런스에서 디자인과 기능 인사이트를 정리해줘.
- 리서치 자료 추가 입력


3. 기본 리서치 자료 인식 규칙
------------------------------

1) 파일명에 "[리서치 결과]"가 들어간 파일을 항상 기본 리서치 자료로 사용한다.
2) 해당 조건에 맞는 파일이 여러 개라면 모두 기본 자료로 사용한다.
3) 기본 자료의 원문은 수정하거나 덮어쓰지 않는다.
4) 각 분석 내용에 어떤 파일에서 가져왔는지 출처를 기록한다.
5) 같은 홈페이지가 여러 파일에 나오면 하나의 대상으로 묶는다.
6) 중복 자료를 묶더라도 발견된 모든 출처는 보존한다.
7) 조건에 맞는 파일이 없으면 임의의 파일을 사용하지 말고 사용자에게 알린다.


4. 추가 리서치 자료 인식 규칙
------------------------------

1) 사용자가 "리서치 자료 추가 입력"이라고 명령하면 이후 제공되는 자료를
   추가 리서치 자료로 인식한다.
2) 추가 자료는 기본 자료를 덮어쓰지 않는다.
3) 추가 자료는 "기본 자료"와 구분하여 출처를 표시한다.
4) 추가 자료로 파일, URL 또는 직접 입력한 텍스트를 받을 수 있도록 설계한다.
5) 기본 자료와 추가 자료에 같은 홈페이지가 있으면 하나로 묶고
   양쪽 출처를 모두 남긴다.


5. 홈페이지별 분석 항목
-----------------------

각 홈페이지를 다음 항목으로 분류하고 분석한다.

1) 기본 정보
   - 홈페이지 또는 서비스 이름
   - URL
   - 업종 또는 분야
   - 주요 대상 사용자
   - 자료 출처

2) 디자인 스타일
   - 전체적인 분위기
   - 색상 사용
   - 글꼴과 글자 크기
   - 이미지와 그래픽 스타일
   - 여백과 화면 밀도
   - 애니메이션 또는 인터랙션

3) 화면 구성과 레이아웃
   - 첫 화면 구성
   - 헤더와 메뉴
   - 주요 콘텐츠 배치
   - 섹션 순서
   - 하단 영역 구성
   - 모바일 화면 대응 방식

4) 메뉴와 사용자 흐름
   - 주요 메뉴 구조
   - 사용자가 처음 보게 되는 정보
   - 주요 행동 버튼
   - 문의, 가입, 구매 등의 이동 과정
   - 사용자가 혼동할 수 있는 지점

5) 문구와 콘텐츠
   - 첫 화면의 핵심 문구
   - 서비스 설명 방식
   - 신뢰를 주는 내용
   - 후기, 사례 또는 수치 사용
   - 행동을 유도하는 문구

6) 주요 기능
   - 검색
   - 회원가입과 로그인
   - 문의 또는 상담 신청
   - 예약 또는 구매
   - 필터와 정렬
   - 기타 특징적인 기능

7) 평가
   - 잘된 점
   - 아쉬운 점
   - 참고할 부분
   - 그대로 적용하면 안 되는 부분
   - 적용 가능한 아이디어


6. 전체 자료 비교 분석
-----------------------

다음 순서와 기준으로 전체 홈페이지 자료를 비교하고 분석한다.

1) 홈페이지별 개별 분석

   - 디자인 특징
   - 화면 구성
   - 사용자 흐름
   - 문구와 콘텐츠
   - 주요 기능
   - 장점과 단점
   - 참고할 부분

2) 비슷한 요소 묶기

   여러 홈페이지에서 비슷하게 나타나는 요소를 하나의 그룹으로 묶는다.
   예: 큰 메인 문구, 제품 화면 이미지, 상단 문의 버튼, 고객 후기, 가격 공개 여부

3) 등장 횟수와 비율 기록

   각 요소가 발견된 홈페이지 수와 전체 홈페이지 대비 비율을 함께 기록한다.

4) 패턴 구분

   - 공통 패턴: 전체 홈페이지 중 30% 이상에서 발견
   - 반복 패턴: 전체 홈페이지 중 10% 이상 30% 미만에서 발견
   - 특이 사례: 10% 미만이지만 참고 가치가 있는 사례

   등장 횟수가 적어도 활용 가치가 높은 아이디어는 특이 사례로 별도 기록한다.

5) 공통점과 차이점 찾기

   - 대부분 사용하는 방식
   - 업종에 따라 달라지는 방식
   - 서로 반대되는 방식
   - 특정 홈페이지에서만 사용하는 방식

6) 각 패턴의 장점과 문제점 분석

   - 패턴 이름
   - 사용한 홈페이지
   - 장점
   - 단점
   - 어울리는 상황
   - 적용 시 주의할 점

7) 최종 인사이트 구분

   - 반드시 참고할 공통 방식
   - 상황에 따라 선택할 방식
   - 차별화를 위해 참고할 독특한 방식

   각 인사이트에는 근거가 된 홈페이지와 자료 출처를 연결한다.

8) 추가 조사 항목 표시

   자료만으로 판단하기 어려운 내용은 추측하지 않고
   "추가 조사 필요", "확인할 내용", "현재 부족한 근거"를 기록한다.


7. 분석 작성 원칙
-----------------

1) 원문에 있는 사실과 분석자의 해석을 구분한다.
2) 중요한 결론에는 반드시 출처를 연결한다.
3) 확인할 수 없는 내용은 사실처럼 작성하지 않는다.
4) 근거가 부족하면 "추정" 또는 "추가 확인 필요"라고 표시한다.
5) 단순 요약에서 끝내지 말고 여러 홈페이지의 공통점과 차이점을 찾는다.
6) 새 홈페이지 제작에 실제로 활용할 수 있는 제안을 작성한다.
7) 자료에 없는 내용을 임의로 만들어내지 않는다.


8. 예상 작업 순서
-----------------

1) 분석 목적을 확인한다.
2) 파일명에 "[리서치 결과]"가 들어간 기본 자료를 찾는다.
3) 추가 입력된 리서치 자료가 있는지 확인한다.
4) 모든 자료에서 홈페이지 목록과 출처를 추출한다.
5) 중복된 홈페이지를 확인하고 하나로 묶는다.
6) 홈페이지별로 디자인, 구성, 흐름, 문구, 콘텐츠, 기능을 분류한다.
7) 홈페이지별 장점, 단점, 참고점을 정리한다.
8) 전체 자료의 공통점, 차이점, 반복 패턴을 분석한다.
9) 적용 가능한 인사이트와 추가 조사 항목을 작성한다.
10) 출처 누락과 근거 없는 결론이 없는지 검사한다.
11) 최종 분석 결과를 정해진 형식으로 저장한다.


9. 확정된 분석 결과물
---------------------

모든 분석 결과는 메모장에서 열 수 있는 UTF-8 형식의 TXT 파일로 저장한다.

1) 홈페이지별 분석

   각 홈페이지마다 다음 내용을 작성한다.

   - 홈페이지 이름
   - URL
   - 업종
   - 디자인
   - 화면 구성
   - 사용자 흐름
   - 문구와 콘텐츠
   - 주요 기능
   - 장점과 단점
   - 참고할 부분

2) 전체 비교 분석

   - 공통점
   - 차이점
   - 반복되는 패턴
   - 눈에 띄는 사례

3) 최종 인사이트

   - 새 홈페이지에 적용할 아이디어
   - 우선 참고할 홈페이지
   - 적용 시 주의할 점
   - 추가 조사가 필요한 내용

결과 파일 분할 규칙:

1) TXT 파일 하나에는 분석 결과를 최대 100개까지만 작성한다.
2) 홈페이지별 분석에서는 홈페이지 하나를 결과 1개로 계산한다.
3) 결과가 100개를 넘으면 다음 TXT 파일을 별도로 만든다.
4) 하나의 홈페이지 분석 내용을 두 파일로 나누지 않는다.
5) 전체 비교 분석과 최종 인사이트도 항목이 100개를 넘으면 별도 파일로 나눈다.
6) 각 파일에는 포함된 결과의 시작 번호와 끝 번호를 표시한다.
7) 파일 이름은 다음 형식을 사용한다.

   - 01_홈페이지별_분석_001-100.txt
   - 01_홈페이지별_분석_101-200.txt
   - 01_홈페이지별_분석_201-300.txt
   - 02_전체_비교_분석_001-100.txt
   - 03_최종_인사이트_001-100.txt

8) 결과가 100개 이하라면 불필요한 다음 파일을 만들지 않는다.


10. 아직 결정하지 않은 내용
----------------------------

다음 항목은 이후 단계에서 사용자와 함께 결정한다.

1) 추가 입력 자료를 한 번만 사용할지 계속 저장할지
2) 결과물을 저장할 폴더
3) 홈페이지별 점수 평가를 사용할지
4) 분석 항목별 중요도 기준
5) URL을 직접 열어서 추가 조사할지
6) 캡처 이미지도 함께 분석할지
7) 기본 자료로 인정할 파일 확장자


11. 현재 확인이 필요한 사항
----------------------------

현재 리서치 폴더에서 확인된 파일:

- [리서치 결과]_SEUMIM_신규_웹사이트_기획_레퍼런스_34선.txt
- [리서치 결과]_SEUMIM_웹사이트_기획_레퍼런스_200선.txt

현재 두 파일의 이름에는 "[리서치 결과]"가 들어가 있다.
따라서 확정된 기본 자료 인식 규칙을 적용하면
두 파일이 자동으로 기본 자료로 선택된다.
